# Сценарий для Claude Code: сайт новой клиники из шаблона

Этот файл — инструкция для ИИ-агента (Claude Code). Пользователь даёт ссылку на этот репозиторий и на
Instagram клиники (иногда ещё 2GIS, сайт, прайс). Задача — собрать данные клиники и перенастроить шаблон
так, чтобы получился готовый сайт этой клиники. Справочник по файлам — `docs/CUSTOMIZE.md`.

## Принципы

- **Не выдумывать фактов.** Цены, врачей, стаж, образование, отзывы, лицензии, рейтинг берём только из
  источников. Чего нет — ставим нейтральную заглушку и вносим в список вопросов к клинике.
- **Отзывы** — только реальные (из хайлайтов/постов клиники), с `isDemo: false`. Нет реальных — `reviews: []`.
- **Фото людей** — не скачивать и не публиковать фото врачей без явного согласия; оставить заглушки-аватары,
  в отчёте попросить у клиники фото.
- **Логины и пароли не вводить.** Если Instagram просит войти — попросить пользователя войти самому в
  открытом браузере и продолжить после этого.
- Тексты писать живо, без канцелярита. Кыргызский перевод делать, но в отчёте пометить, что нужна
  проверка носителем.
- Демо-клинику «Арча Дент» полностью убрать: название, адрес, телефоны, врачи, отзывы, пометки «демо».

## Шаги

### 1. Проект
1. Склонировать шаблон в новую папку (имя — латиницей по названию клиники), `git remote remove origin`.
2. `npm i`, `cp .env.example .env`, сгенерировать `SESSION_SECRET`, задать `ADMIN_PASSWORD`
   (сообщить пользователю, где он лежит, но не печатать в чат), `npx prisma migrate dev`.
3. Прочитать `README.md`, `docs/CUSTOMIZE.md`, `AGENTS.md` (в этой версии Next.js есть отличия от
   привычных API — документация лежит в `node_modules/next/dist/docs/`).

### 2. Сбор данных
Открыть Instagram клиники в браузере и пройти:
- **шапку профиля**: имя, описание (био), ссылки (WhatsApp `wa.me`, Telegram, сайт, Taplink/Linktree —
  открыть и их), кнопки «Позвонить»/«Адрес», категорию;
- **хайлайты (актуальное)**: «Цены», «Прайс», «Услуги», «Врачи»/«Команда», «Отзывы», «Акции», «Контакты»,
  «О нас» — здесь обычно прайс и врачи;
- **последние 30–60 постов**: знакомство с врачами (ФИО, специализация, стаж, образование), услуги,
  оборудование, год открытия, «нам N лет», акции; подписи постов.

Затем 2GIS (https://2gis.kg/bishkek, поиск по названию): точный адрес, часы работы, телефоны, рейтинг,
координаты, ссылка на карточку (`twoGisUrl`). Если пользователь дал сайт клиники — взять и оттуда.

Логотип: аватар Instagram (скачать в максимальном размере) → `public/brand/`. Если это фото, а не логотип,
или качество плохое — не использовать, оставить фирменный знак шаблона и попросить исходник у клиники.

Цвета бренда: по логотипу и оформлению постов. Если близко к мятной/синей/бежевой — взять готовую тему,
иначе создать свою в `src/config/themes.ts` (см. `docs/CUSTOMIZE.md`, п. 5).

Сохранить собранное в `docs/clinic-data.md` (что откуда взято — со ссылками), чтобы было что показать
клинике и на что сослаться.

### 3. Перенастройка
По `docs/CUSTOMIZE.md`:
1. `src/config/clinic.ts` — все данные клиники (ru + ky), часы, тема, `logoUrl`, юрлицо (если неизвестно —
   оставить название клиники и пометить вопрос).
2. `prisma/seed-data.ts` — категории, услуги с ценами «от …» и длительностью, врачи (slug транслитом,
   услуги, график — если неизвестен, по часам клиники), FAQ (адаптировать под клинику), отзывы.
   Если прайса нет совсем — оставить 10–15 типовых услуг без выдуманных цен нельзя: цены нужны для сайта,
   поэтому поставить ориентировочные рыночные цены Бишкека и **явно** вынести это в список вопросов.
3. `messages/ru.json` и `messages/ky.json` — убрать `footer.disclaimer` (демо), поправить `footer.license`,
   преимущества `home.benefits` и оборудование `about.equipment` под реальную клинику.
4. `src/content/privacy.ts` — проверить, что плейсхолдеры подставятся корректно.
5. Если меняли шрифты — проверить кыргызские ң, ө, ү (см. README).

### 4. Проверка
```bash
SEED_DEMO=false npm run db:seed
npm test && npm run lint && npm run build
npm run dev
```
Открыть сайт в браузере: главная (ru и `/ky`), услуги, врач, полный сценарий записи `/booking`,
админка `/admin` (запись видна). Проверить мобильную ширину (375px). Исправить всё, что выглядит криво
(длинные названия, переносы, пустые блоки).

### 5. Отчёт пользователю
- Что сделано и где посмотреть (`npm run dev` → http://localhost:3000, админка /admin).
- Таблица «данные → источник».
- **Список вопросов к клинике**: чего не нашли, что поставлено примерно (цены, графики врачей, юрлицо/ИНН,
  лицензия, фото врачей, исходник логотипа, ссылка на виджет 2GIS, реальные отзывы), проверка кыргызского.
- Следующие шаги: деплой на Vercel + Postgres (README).
- Коммиты и пуш — только если пользователь дал репозиторий и попросил.
